## 1. Executive Summary & Inventory Coverage

This inventory documents every application route, UI page, API endpoint, server action, role boundary, and database integration across the SimpleIn Schools platform.

The system encompasses **4 distinct user personas**:
1. **School Administrator (`SCHOOL_ADMIN`)** — Full institutional, academic, financial, and user management.
2. **Faculty / Teacher (`TEACHER`)** — Classroom management, daily attendance, marks entry, homework assignment, timetable, notices.
3. **Parent / Guardian (`PARENT`)** — Family portal, multi-child switching, attendance tracking, results, term report cards, fee dues, notices.
4. **Student / Scholar (`STUDENT`)** — Self-service scholar terminal, class timetable, homework submissions, published results, past year question papers (PYQs), fee statements.

## 3. Preserved Architecture & Integrity Guardrails

1. **Zero Mock Regression:** All data queries link to Supabase PostgreSQL with verified session context and RLS policies.
2. **Strict School Isolation:** The multi-tenant partition key (`school_id`) is strictly bound to the authenticated user's session token and re-verified on every service query.
3. **RBAC Invariants:** Public registration does not grant administrative privileges. Roles (`SCHOOL_ADMIN`, `TEACHER`, `PARENT`, `STUDENT`) are verified server-side on every route and API handler.
4. **Institutional Login Design:** Staff portal (Admin/Teacher) and Family portal (Parent/Student) remain cleanly isolated with dedicated identity resolution and unified fallback.
